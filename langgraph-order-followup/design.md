## Context

原接口每个请求单独运行。DeepSeek 查单工具和 PostgreSQL 查询都可从 Python 调用。

## Goals / Non-Goals

- 先问退货问题，再用一个订单号补齐所需信息。
- 同一对话继续使用第一轮选择的退货期限。
- 本阶段的对话状态只在本机服务进程内保存。

## Decisions

- 用 LangGraph 的条件边判断是否需要追问。`interrupt()` 暂停并保存检查点。`Command(resume=...)` 补交订单号。
- 服务器生成会话 ID。只有等待输入的会话能继续；查询结束后会话结束。
- 临时查询故障保留待办节点，允许用同一条补充消息重试。
- 已有 `query_after_sales()` 负责模型工具验证和数据库查询。
- 前端在等待补充时显示原始问题，锁定最初的退货期限。开始新查询时清空当前会话。

## Risks / Trade-offs

- [服务重启清空会话] → 如果继续提交过期 ID，提示从头查询。
- [同一会话重复提交] → 同步调用按会话串行处理，避免并行修改检查点。
