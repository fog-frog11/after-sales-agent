## Context

查单会话目前使用内存检查点，浏览器等待订单号时也只保存当前页面状态。

## Goals / Non-Goals

- 同一标签页刷新后，恢复原问题和当前追问。
- Python 服务重启后，同一个已持久化的会话 ID 可继续查单。
- 此变更覆盖买家查单会话。

## Decisions

- 配置 PostgreSQL 时使用官方 PostgresSaver，将检查点放入单独 schema。无数据库参数时沿用内存演示。
- 浏览器 sessionStorage 仅保存等待中的 UUID。恢复接口提供可显示的业务结果。
- 已结束或失效的会话返回对应状态，用户可开始新查询。
- 对已完成的同一条回复，重发时返回保存结果。

## Risks / Trade-offs

- [保存状态时数据库短暂不可用] → 接口返回可读的 HTTP 503，浏览器保留待恢复会话 ID。
