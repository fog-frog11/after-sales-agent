## 数据和业务边界

- 使用 Olist 在 Kaggle 发布的订单 CSV。按源订单编号排序，每类默认抽 50 笔。优先覆盖正常送达、延迟送达、发货后未签收且超期、已取消。跳过无法归类的记录并统计数量。
- `OL-` 后拼接源订单 ID 的前 10 位，导入前检查编号冲突。主键使用完整源订单 ID。导入在一个事务内执行，重复导入跳过已有记录。读取和导入只使用订单状态及相关日期，不使用客户字段。
- 采用 2018-10-17 作为历史查询日，与源数据末批下单日一致。未签收超期按预计日期与该日期比较，已签收延误按实际与预计日期比较。
- LangGraph 复用买家追问流程，遇到 Olist 编号走独立的只读查询节点。页面标明 Olist 来源和历史日期。政策和人工工单继续使用项目已有的模拟店铺订单。
