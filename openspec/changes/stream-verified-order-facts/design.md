## 实现

浏览器通过独立的按行 JSON 入口接收同一轮的订单事实与最终结果。订单和会话校验使用既有入口中的同一套规则。临时响应不写入历史，LangGraph 完成后保存整轮。若连接中断，已展示的事实留在气泡并显示重试提示。

京东明确的件数、金额或物流问法用规则直接路由。混合问法的订单部分先读取 PostgreSQL，事实就绪后才进行 Function Calling、MCP 查询和答复复核。条款依据和最终引用继续按订单经营渠道校验。

## 本机测量

从已导入数据选择一笔自营和一笔第三方订单，每种问题在每笔订单上跑两次。切换前后共 24 次实际请求。两轮全部通过商品核对和适用范围检查。以下为各组中位数。

| 场景 | 原先首条 | 现在首条 | 原先完整 | 现在完整 |
| --- | ---: | ---: | ---: | ---: |
| 查件数 | 1,435 ms | 61 ms | 1,435 ms | 61 ms |
| 查件数和条款 | 9,317 ms | 67 ms | 9,317 ms | 7,794 ms |
| 只问条款 | 8,115 ms | 8,310 ms | 8,115 ms | 8,310 ms |

混合问题的首条 P95 从 10,253 ms 降到 77 ms，完整答复 P95 从 10,253 ms 降到 8,441 ms。每组四次，分位数只描述本轮样本。优化后混合问题的 Milvus 检索中位数约 53 ms，MCP 阶段约 2,841 ms，模型起草约 1,742 ms，答复复核约 1,558 ms。Milvus 耗时包含在 MCP 阶段内。
